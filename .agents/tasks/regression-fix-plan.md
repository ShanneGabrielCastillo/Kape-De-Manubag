## ISSUE 1 — Order Management sidebar label is missing

### Root Cause Diagnosis

The Order Management `<a class="sidebar-link">` in `templates/base_admin.html` is **missing its `<span class="nav-label">` entirely**. The element was accidentally omitted during the Lucide migration.

Every other working nav item follows this structure:
```html
<a class="sidebar-link ...">
  <span class="nav-icon"><i data-lucide="..." class="nav-icon" aria-hidden="true"></i></span>
  <span class="nav-label">Label Text</span>
  <span class="sidebar-tooltip" aria-hidden="true">Label Text</span>
</a>
```

The Order Management link (lines ~49–58 of `base_admin.html`) currently reads:
```html
<a href="{% url 'orders:order_list' %}" class="sidebar-link ..." id="sidebar-orders-link" aria-label="Order Management">
  <span class="nav-icon"><i data-lucide="clipboard-list" class="nav-icon" aria-hidden="true"></i></span>
  {# JS-controlled badge #}
  <span id="sidebar-awaiting-badge" class="sidebar-awaiting-badge" aria-hidden="true" style="display:none">0</span>
  <span class="sidebar-tooltip" aria-hidden="true">Order Management</span>
</a>
```

The `<span class="nav-label">Order Management</span>` **was never inserted** (or was removed) when the emoji icon was replaced with the Lucide `<i>` tag. The badge and tooltip spans are both present, but the visible label is gone.

**Confirmed**: No CSS rule suppresses only the Order Management label. The collapse rule `.sidebar-collapsed .sidebar .sidebar-link .nav-label { display: none; }` targets `.nav-label` class — if the span existed it would be hidden only when collapsed, exactly as intended. The problem is structural: the span is absent from the HTML.

**The badge (`<span id="sidebar-awaiting-badge">`) must stay in its current position** (after the label, before the tooltip) so the existing JS badge logic and the collapsed-sidebar absolute-positioning rule both continue to work correctly.

### Fix

**File:** `templates/base_admin.html`  
**Location:** Inside the Order Management `<a class="sidebar-link" id="sidebar-orders-link">` element, between the `.nav-icon` span and the `#sidebar-awaiting-badge` span.

Insert the missing label span so the element reads:

```html
<a href="{% url 'orders:order_list' %}" class="sidebar-link {% if request.resolver_match.app_name == 'orders' and request.resolver_match.url_name in 'order_list,order_detail,update_status,process_payment,accept_order,verify_gcash_payment,reject_gcash_payment,print_receipt,quick_status_advance' %}active{% endif %}"
   id="sidebar-orders-link"
   aria-label="Order Management">
  <span class="nav-icon"><i data-lucide="clipboard-list" class="nav-icon" aria-hidden="true"></i></span>
  <span class="nav-label">Order Management</span>
  <span id="sidebar-awaiting-badge"
        class="sidebar-awaiting-badge"
        aria-hidden="true"
        style="display:none">0</span>
  <span class="sidebar-tooltip" aria-hidden="true">Order Management</span>
</a>
```

**What to add:** `<span class="nav-label">Order Management</span>` on the line immediately after the `.nav-icon` span and immediately before the `#sidebar-awaiting-badge` span.

**Do not:**
- Move or remove `#sidebar-awaiting-badge`
- Change the active-state Django template logic
- Change the `aria-label` attribute
- Change the `id="sidebar-orders-link"` attribute
- Touch any other nav item

### Verification

- **Expanded sidebar**: Order Management shows `[clipboard-list icon] Order Management [badge if count > 0]`
- **Collapsed sidebar**: Only the clipboard-list icon shows; label hidden by `.sidebar-collapsed .sidebar .sidebar-link .nav-label { display: none; }` — the existing CSS rule already handles this correctly
- **Badge**: `#sidebar-awaiting-badge` remains positioned after the label in the flex row on expanded; the existing collapsed-state CSS repositions it as an absolute overlay over the icon automatically

## ISSUE 3 — Visible gap above the topbar/sidebar

### Root Cause Diagnosis

After thoroughly reading all CSS files, the cause is **not** `body { margin: 8px; }` (the reset rule `*, *::before, *::after { box-sizing: border-box; margin: 0; padding: 0; }` in `main.css` zeroes all margins globally, which includes the browser's default body margin).

The actual cause is in the **sidebar icon CSS added during the Lucide migration**, at the bottom of `static/css/main.css`. There are two conflicting `.nav-icon` rule sets that both set `display`:

**Rule set 1** (in the "LUCIDE ICON SYSTEM" section, ~line 2253):
```css
.nav-icon {
  width: 20px;
  height: 20px;
  display: inline-flex;
  align-items: center;
  justify-content: center;
  flex-shrink: 0;
  text-align: center;
}
```

**Rule set 2** (added after the LUCIDE ICON SYSTEM section as a duplicate block, ~line 2310):
```css
[data-lucide] {
  display: inline-block;
  vertical-align: middle;
  flex-shrink: 0;
}
.nav-icon[data-lucide],
.nav-icon > svg {
  width: 18px;
  height: 18px;
}
```

The HTML uses a **double-nesting pattern** for the sidebar icons:
```html
<span class="nav-icon">
  <i data-lucide="layout-dashboard" class="nav-icon" aria-hidden="true"></i>
</span>
```

Both the `<span>` and the `<i>` carry `class="nav-icon"`. The outer `<span class="nav-icon">` is a flex item inside `.sidebar-link { display: flex; align-items: center; gap: 10px; }`. The `[data-lucide]` rule sets `display: inline-block` on the `<i>`, which overrides the `inline-flex` set by `.nav-icon`, but more critically the `vertical-align: middle` on `inline-block` elements causes the **browser to insert baseline alignment space** (the "inline gap") above/below the element.

This baseline gap propagates upward: the `<span class="nav-icon">` is sized to its content, and since its child `<i>` has `vertical-align: middle` + `display: inline-block`, the span acquires implicit top/bottom line-height spacing. When Lucide's `createIcons()` runs, it replaces the `<i>` with an `<svg>` — SVG elements also inherit the `vertical-align: middle` from the `[data-lucide]` rule, compounding the inline gap.

This doesn't cause a gap on `.sidebar-link` items themselves (they are `display: flex`), but it **does** affect the `.sidebar-brand` section which contains `<div class="brand-logo">☕</div>` (inline content) and other elements, and more importantly it compounds with the `<header class="topbar">` which is a flex container containing `<button>` and `<span>` with inline Lucide icons. The `vertical-align: middle` on the `<i data-lucide="menu">` topbar icon causes the button height to expand slightly beyond `var(--header-h): 65px`, and since `.topbar { position: sticky; top: 0; }` is used on desktop, the first pixel of the sticky topbar sits exactly at `top: 0` — but the `<main class="main-content">` starts at `margin-left: var(--sidebar-w)` with no explicit `padding-top`, while the topbar is sticky inside it. The gap appears because the `<main>` element's first child is the sticky `.topbar`, and the browser reserves line-height space above it due to the `vertical-align: middle` on the inline `[data-lucide]` content within the topbar's flex children.

**The concrete fix:** Remove `vertical-align: middle` from the `[data-lucide]` rule (or change `display: inline-block` to `display: inline-flex`, which eliminates baseline gaps). This prevents the browser from inserting any inline baseline space around Lucide SVG icons anywhere in the layout.

Additionally, the double-entry in `main.css` (the second `[data-lucide]` block that re-declares sizing rules already set in the LUCIDE ICON SYSTEM section) should be collapsed to remove the duplicate. The duplicate block was added during migration and creates specificity confusion.

### Fix

**File:** `static/css/main.css`  
**Location:** The second Lucide rules block near the end of the file (after the `/* END LUCIDE ICON SYSTEM */` comment), approximately lines 2308–2340.

#### Step A — Fix the `[data-lucide]` base rule

Change:
```css
[data-lucide] {
  display: inline-block;
  vertical-align: middle;
  flex-shrink: 0;
}
```

To:
```css
[data-lucide] {
  display: inline-flex;
  vertical-align: middle;
  flex-shrink: 0;
}
```

`inline-flex` containers do not participate in baseline alignment the way `inline-block` does, so the browser stops inserting implicit top spacing above the icon element. The `vertical-align: middle` can remain (it has no effect on `inline-flex` in a flex parent — flex layout ignores it — and is harmless in inline contexts).

#### Step B — Remove duplicate size declarations

The second block re-declares sizes that the LUCIDE ICON SYSTEM block already sets correctly. Remove the following redundant rules (they appear after the `/* END LUCIDE ICON SYSTEM */` comment and duplicate the sizes in the block above):

```css
/* Remove these duplicate rules: */
.nav-icon[data-lucide],
.nav-icon > svg {
  width: 18px;
  height: 18px;
}

.btn-icon[data-lucide],
.btn-icon > svg {
  width: 16px;
  height: 16px;
}

.topbar-icon[data-lucide],
.topbar-icon > svg {
  width: 18px;
  height: 18px;
}

.status-icon[data-lucide],
.status-icon > svg {
  width: 14px;
  height: 14px;
}

.action-icon[data-lucide],
.action-icon > svg {
  width: 32px;
  height: 32px;
}

.chat-icon[data-lucide],
.chat-icon > svg {
  width: 20px;
  height: 20px;
}

.stat-icon[data-lucide],
.stat-icon > svg {
  width: 24px;
  height: 24px;
}
```

The LUCIDE ICON SYSTEM block above already sets these sizes correctly via the class rules (`.nav-icon { width: 20px; height: 20px; }`, etc.), and the `svg` targeting within those wrappers is covered by `.nav-icon svg, .nav-icon [data-lucide] { width: 100%; height: 100%; }`. The duplicate `[data-lucide]`-suffixed rules override the intended sizes (e.g. `.nav-icon` says 20×20 but `.nav-icon[data-lucide]` then forces 18×18 on the icon itself).

**What to keep** from the second block: only the corrected `[data-lucide]` base rule (Step A above).

- **Mobile**: The fixed topbar (`position: fixed; top: 0`) already avoids the issue at `max-width: 575.98px`, but confirm no unexpected spacing at 320px–480px
- **Sidebar**: Icons remain correctly sized and visible in expanded and collapsed states
- **Topbar**: Icons remain correctly sized; toggle button, order badge icon, and page title alignment unchanged
